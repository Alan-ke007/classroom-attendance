## 1. 已锁定决策（需求基线）

| 维度 | 结论 |
|------|------|
| 重做范围 | **全栈重做**（后端 + 算法 + 三前端） |
| 使用场景 | 桌面（管理/教师）+ 手机（学生小程序）+ 大屏（监控/数字孪生）三者兼顾 |

## 2. 产品定位与目标用户

- **定位**：高校课堂智能考勤 + AI 行为分析一站式平台。
- **用户画像**：
  - **管理员**：系统/用户/数据全局管理，重数据看板与配置。
  - **教师**：考勤发起、请假审批、行为监控、课堂质量评估。
  - **学生**：扫码签到、查考勤/课表/行为、收通知、互动。
- **设备/场景**：桌面（办公管理）、手机（学生高频签到）、大屏（监控/数字孪生展示）。

## 3. 功能范围：场景驱动的功能清单

> 基于 `FUNCTIONAL_ANALYSIS_SCENARIO.md` 的场景分析结论：9 大模块方向正确，但**不能平级对待**。下方按 MoSCoW 分层并标出真实刚需缺口。设计原则——**保留但分层**：既尊重"保留 9 模块"决策，又避免首版背上全量重负（详见该文档 §4/§5）。

### 3.1 功能优先级（MoSCoW）

| 层级 | 功能 | 理由 |
|------|------|------|
| **Must** | 多方式签到（含人脸防代签）、课程/班级/学生管理、请假（附件+审批）、YOLOv8 行为检测、统计看板、三角色权限、消息通知 | 场景 A/B/C/D 天天用，不做不成产品 |

### 3.4 核心价值闭环（资源优先投入）

发起签到（人脸防代签） → 实时看板/异常 → 行为监控（YOLOv8） → 请假关联 → 自动预警（辅导员） → 统计报表 → 导出/对接教务。

### 3.5 非目标（Out of Scope，首版不做）

- **家长通知**：大学生为成年人，无需（K12 才需）。
- **教务系统双向写回**：仅 inbound 导入/同步，不回写教务。
- **复杂智能排课算法**：排课非本系统职责。
- **独立 IM**：用微信/QQ 群替代，不自建聊天（或仅做轻量留言）。
- **跨校多租户**：首版单校单租户。

## 4. 非功能需求

- **可访问性**：WCAG 2.1 **AA** —— 4.5:1 对比度、可见 `:focus-visible` 焦点环、交互元素 ≥ 44px、尊重 `prefers-reduced-motion`。（旧系统缺口，新系统从地基内建）
  - **性能**：Web 首屏 < 2s；长列表虚拟滚动；大屏动效 60fps；API P95 < 300ms。（目标值，落地时校准）
- **响应式**：Web 桌面优先 + 平板适配；小程序自适应多机型。
- **国际化**：**仅中文**（首版）；代码层预留 i18n 结构，不实现多语言包。
- **部署**：**Docker Compose 一键编排**（后端 / 算法 / Web / 小程序后台），**优先适配校园内网**；公有云作为备选。（推荐值）

## 5. 技术架构（现代栈）

**Monorepo（pnpm workspace）**
```
smartclass/                      # 新仓库根
├── apps/
│   ├── web-admin/               # Vue3 + TS + UnoCSS（管理/教师端，玻璃轨道）
│   ├── web-student/             # Vue3 + TS + UnoCSS（学生端 Web）
│   └── miniprogram/             # uni-app（Vue3）学生/教师小程序
├── services/
│   ├── backend/                 # Spring Boot 3（保留，重写业务 + OpenAPI）
│   └── algorithm/               # FastAPI + YOLOv8（Flask→FastAPI 升级）
└── packages/
    └── design-system/           # ★ 共享：design tokens + 核心组件 + 文档(Storybook)
```

- **前端**：Vue 3 + **TypeScript** + **UnoCSS**（原子化，配 token 极顺）+ **自建轻量组件库**；Element Plus 仅作个别复杂组件（表格/表单）兜底。**彻底脱离组件库默认样式绑架，从根上消灭 `!important` 灾难。**
- **后端**：Spring Boot 3 保留，重写业务层 + 统一 API 契约 + 补 **OpenAPI** 文档。
- **算法**：Flask → **FastAPI**（异步、自动 OpenAPI、类型安全），YOLOv8 不变。
- **小程序**：uni-app（Vue3），复用 Web 的 Vue 技能，学生端迁移方便。
- **图表**：ECharts（大屏用 canvas 渲染保性能）。
- **设计系统工程化**：design tokens 单一来源（CSS 变量 + UnoCSS theme）+ Storybook 组件文档 + ESLint/Prettier。

## 6. 设计系统蓝图：两份方向对比

### Direction A（已确认基底）· 双轨
- **轨道 A 玻璃后台**（管理/学生 Web）：毛玻璃卡片、圆角（12–18px）、克制霓虹点缀（主操作/状态）、柔和留白。
- **轨道 B 粗野大屏**（监控/数字孪生）：硬边硬影、扫描线、大写 mono 数字、霓虹辉光。
- **共享品牌**：cyan `#00E5FF` / magenta `#E040FB` / yellow `#FFD600` 霓虹 + 中性灰阶；两套作用域 `.track-glass` / `.track-brutal`。
- **组件状态**：4 态（default/hover/active/disabled）+ loading + `:focus-visible` 焦点环。
- **优点**：冲击力最强，大屏 wow 效果足，保留现有品牌基因。
- **风险**：两套语言需严谨管理，否则易回到旧系统的"打架"——靠共享 design-system 包约束。

### Direction B（全新方向备选）· 静谧科技 Quiet-Tech
- **单一品牌色**：沉稳 Indigo `#4F46E5` 为主；仅"实时/AI"状态用一抹 Cyan 点亮（语义化，不滥用）。
- **视觉**：大留白、圆角 16px、柔和分层阴影（低透明度）、微动效；light 默认 + dark 专注模式。
- **监控大屏**：切深色专注模式，靠单色强调 + 克制动效点亮"实时/AI"，不靠硬边轰炸。
- **优点**：极致统一、稳重、教育场景专业感强、实现与维护风险低、三端一致性最容易保证。
- **取舍**：牺牲一点"科幻冲击力"，换全局一致性与易用性（更贴合"美观+易用+符合习惯"）。

| 维度 | A 双轨 | B 静谧科技 |
|------|--------|-----------|
| 冲击力/辨识度 | 强（大屏 wow） | 中（稳重专业） |
| 三端一致性难度 | 中（需严管双语言） | 低（单一语言） |
| 易用/教育适配 | 良 | 优 |
| 实现风险 | 中 | 低 |
| 品牌基因延续 | 强（沿用霓虹） | 弱（换新调性） |

> **请你拍板**：选 A / 选 B / 或融合（如 B 为全局基调 + A 的粗野大屏仅留给数字孪生）。

## 7. 分阶段里程碑（建议）

- **P0 地基**：monorepo 搭建 + `packages/design-system`（token + 核心组件 + Storybook）+ 后端骨架 + OpenAPI 契约。★ 约 1 周。
- **P1 主干闭环（Must 层）**：认证 / 考勤（含人脸防代签） / 请假 / 行为 / 统计 在 Web 管理端先通；课表对接教务与辅导员预警（Should 层）紧随。★ 2–3 周。
- **P2 三前端 + 视觉**：Web 学生端、小程序、双轨/静谧视觉落地；共享组件全面接入。★ 2–3 周。
- **P3 大屏与长尾**：数字孪生大屏、聊天、文件、公告、日志、导入导出。★ 2 周。
- **P4 收口**：WCAG AA 无障碍审计、性能优化、跨端回归测试。★ 1 周。

> 时间为单机估算 ★，实际取决于人力与最新版代码现状。
